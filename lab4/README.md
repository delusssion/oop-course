**Вариант 4.** Мир D — небесные тела: `Star`, `Planet`, `Moon` (базовый вариант).

## Контракт классов

```
            CelestialBody (абстрактный)
            mass_, radius_
            metric() = G*M/R^2
            name(), print(), read(), clone()  -- чисто виртуальные
           /            |             \
       Star           Planet           Moon
   temperature_    temperature_    orbit_period_, rotation_period_
   stellarClass()  isHabitable()   tidallyLocked()
```

| Член `CelestialBody` | Вид | Почему так |
|---|---|---|
| `virtual ~CelestialBody()` | виртуальный | чтобы `delete` через указатель на базу вызывал деструктор наследника |
| `double metric() const` | виртуальный с реализацией | формула `g = G·M/R²` одинакова для всех трёх тел, поэтому реализована один раз в базе; наследник может переопределить |
| `const char* name() const` | чисто виртуальный | имя класса знает только наследник |
| `void print(std::ostream&) const` | чисто виртуальный | у каждого тела свой набор полей |
| `void read(std::istream&)` | чисто виртуальный | у каждого тела свой набор полей; не `const`, потому что меняет объект |
| `CelestialBody* clone() const` | чисто виртуальный | нужен коллекции для глубокого копирования без срезки |
| `explicit operator double() const` | обычный | возвращает `metric()`; `explicit`, чтобы тело случайно не превращалось в число |
| `operator==`, `operator!=` | обычные | сравнение по `metric()` с точностью `EPS = 1e-6` |
| `operator<<`, `operator>>` | свободные функции | оператор не может быть виртуальным, поэтому он вызывает виртуальные `print` / `read` |

Константные методы: `metric`, `name`, `print`, `clone`, геттеры и тип-специфичные
методы ничего не меняют в объекте, поэтому помечены `const` — их можно вызывать у
константных ссылок (например, в `operator<<` и в `totalMetric`).

Тип-специфичные методы (вызываются после `dynamic_cast`):

* `Star::stellarClass()` — `"O"` (≥ 30000 K), `"B"` (≥ 10000), `"A"` (≥ 7500), `"F"` (≥ 6000), `"G"` (≥ 5200), `"K"` (≥ 3700), иначе `"M"`;
* `Planet::isHabitable()` — `|T − 290| < 60` и `g ∈ [5, 15]`;
* `Moon::tidallyLocked()` — `|T_orbit − T_rot| < eps·T_orbit`.

Инварианты: масса, радиус, температура и периоды строго больше нуля.
Конструктор с некорректными значениями бросает `std::invalid_argument`,
`read` при некорректных значениях ставит `failbit` и не меняет объект.

### Копирование базового класса

Копирующий конструктор `CelestialBody` — `protected`, присваивание удалено.
Так нельзя случайно скопировать объект «по базе» (срезка), но наследники
могут копироваться, что нужно для `clone()`.

## Коллекция и владение

`BodyCollection` хранит собственный динамический массив `CelestialBody**`.
Коллекция **владеет** объектами: `add(new Star(...))` передаёт ей указатель,
а удаляет объекты только она (`remove`, `clear`, деструктор). Каждый объект
удаляется ровно один раз, а благодаря виртуальному деструктору вызывается
деструктор нужного наследника.

Правило пяти:

* копирующий конструктор — глубокая копия через `clone()`;
* копирующее присваивание — copy-and-swap;
* перемещающие конструктор и присваивание забирают массив и обнуляют источник;
* деструктор удаляет все объекты и сам массив.

Методы: `add`, `remove`, `clear`, `size`, `empty`, `operator[]`, `totalMetric`, `printAll`.

## Формат ввода и вывода

Все величины в СИ.

| Класс | Ввод | Вывод |
|---|---|---|
| Star | `M R T` | `Star: M=... kg R=... m T=... K g=... m/s^2` |
| Planet | `M R T` | `Planet: M=... kg R=... m T=... K g=... m/s^2` |
| Moon | `M R T_orbit T_rot` | `Moon: M=... kg R=... m T_orbit=... s T_rot=... s g=... m/s^2` |

Поля в выводе идут в том же порядке, что и при вводе.
